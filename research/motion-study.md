# Motion study — Lattafa Nigeria pitch

Reviewed 23 October 2026. Scope: eight text, image and interface transition families; a selection for the existing React 19 + `framer-motion` 12.23.24 storefront. This is research and implementation guidance, not a claim that these effects have already been implemented or profiled.

The design judgment below applies the project's **The object, large** direction (seed `487598090`) and the taste skill's motion guidance: preserve the bottle photograph, keep the shopping interface fast, give text its own choreography, and reserve one conspicuous move for the first screen. The HD photograph carries the hero; neither a rotating 3D bottle nor the unrelated footwear clip is appropriate.

## Chosen composition

Use five main families: **masked text, short typing, crossfades, shared-layout selection, and collection/filter choreography**. Their roles differ: the heading introduces, the scent phrase expresses, the crossfade compares, the selection surface orients, and the collection transition confirms. Small press/focus feedback is baseline interface behavior.

Suggested placement:

- Hero: two-line masked headline; supporting sentence visible immediately; HD bottle photograph stable or settling by only 1.02→1. No loading screen, video shoe, synthesized bottle, or first-screen typing delay.
- Scent finder: one short phrase typed once (for example, “Find your signature.”), with the actual choices and action already available. Final wording must fit the layout at 390 px.
- Catalog: immediate brand and gender filtering, with a brief position/opacity transition; first entrance stagger kept under 360 ms total.
- Fakhar comparison: real Black/Rose images crossfade; selected control surface slides only inside its track; note copy dissolves cleanly.
- Cart, search, product details and mobile navigation: use the existing accessible Radix dialog primitives. Drawers can use a 250 ms transform/opacity transition, closing in 180 ms. Focus trapping, Escape, close labels and focus restoration remain the primitive's job. This is a functional application of the same enter/exit family, not a sixth decorative treatment.

## Shared rules for implementation

These values are design recommendations inferred from the official APIs and the local taste guidance; they are not performance guarantees from the source pages.

- Keep `framer-motion` imports. The current docs show `motion/react`, but the installed package already provides the required APIs. No migration or dependency additions are necessary.
- Use `MotionConfig reducedMotion='user'` plus `useReducedMotion()` for explicit CSS/typewriter changes. Motion's [reduced-motion hook](https://motion.dev/docs/react-use-reduced-motion) responds to the user's system setting; MDN describes the corresponding [CSS media feature](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion).
- Keep essential content in its final HTML form. Animations may enhance entrance; they must not leave content hidden when an observer or script fails.
- Use transform and opacity for routine motion. Do not animate large text blur, letter spacing, image dimensions, or page height on every frame. Scope `will-change` to active animation rather than every card permanently.
- No infinite typing/backspacing, autoplay carousel with no pause control, scroll hijacking, or motion that prevents immediate reading and buying.
- Keep HD image width/height or aspect ratio explicit, choose responsive source sizes, preload only the first visible campaign image, and decode before a product-photo swap.
- Verify at 1440, 768 and 390 px plus reduced motion: final text visible; no clipping of descenders; no horizontal overflow; controls at least 44 px; a keyboard can reach and operate each action.

## Evidence boundary

Observed: official documentation supports these animation families; the project has React 19, Framer Motion 12, Radix dialogs and Tailwind 4, and already uses reduced-motion hooks and AnimatePresence. The existing Fakhar component rotates/translates product images substantially; replacing that treatment with real-photo crossfades is an editorial recommendation.

Not established by this study: that any unimplemented effect meets the project's frame budget, that all final assets are HD, or that the current site passes accessibility or visual inspection. No app code, installation, deployment, or paid component was changed by this research task.
